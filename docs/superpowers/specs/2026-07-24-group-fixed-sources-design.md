# 群组固定分析来源设计

日期：2026-07-24

## 目标

允许群成员为某个飞书群固定最多 5 个分析来源。后续成员在该群中 `@机器人` 发起普通分析时，服务自动加入这些来源，不再要求每次粘贴链接。固定配置持续生效，直到群成员显式解绑。

支持的固定来源与现有 Agent 一致：

- Docx
- Wiki
- Sheets
- Base

私聊不支持固定来源配置，也不会读取任何群组固定来源。

## 交互

服务在调用模型前确定性识别以下命令：

```text
@机器人 固定来源 <1-5 个飞书链接>
@机器人 查看固定来源
@机器人 解绑来源 <1-5 个飞书链接>
@机器人 清空固定来源
```

群内所有成员都可以执行这些命令，不查询群主或管理员身份。配置命令不会调用模型，也不能与分析请求混用。用户在同一条消息中要求固定并分析时，服务先完成固定并提示用户重新发起分析。

命令语义：

- `固定来源`：校验链接类型，规范化 URL，去重后追加。已存在的链接不会重复写入，并在结果中标记为已固定。新增后总数不得超过 5。
- `查看固定来源`：按添加时间列出来源类型、链接和添加人；没有配置时明确提示。
- `解绑来源`：仅删除本群中与规范化 URL 精确匹配的来源；不存在的链接单独报告。
- `清空固定来源`：删除本群全部固定来源。

解绑操作可通过重新绑定恢复，因此不增加交互确认卡。

## 数据模型

在现有 SQLite 数据库新增 `group_sources` 表：

```sql
CREATE TABLE IF NOT EXISTS group_sources (
  chat_id TEXT NOT NULL,
  normalized_url TEXT NOT NULL,
  source_kind TEXT NOT NULL,
  added_by TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (chat_id, normalized_url)
);
```

`chat_id` 隔离不同群组。`normalized_url` 用于唯一性和合并去重，保存完整可用的 HTTPS 飞书资源链接。`source_kind` 仅允许 `document`、`wiki`、`sheet`、`base`。`added_by` 用于查看配置和审计。

配置跨服务重启持久化，不设置自动过期时间。

## 来源构建流程

普通群聊分析请求按以下顺序构建来源：

1. 从当前消息解析文本和临时飞书链接。
2. 从 SQLite 读取当前 `chat_id` 的全部固定来源。
3. 使用规范化 URL 合并固定来源和临时链接，重复链接只保留一个。
4. 为合并后的链接生成本轮不可预测的 `source_id`。
5. 将来源清单放入本轮 `RunContext`，保持现有工具只接受 `source_id` 的边界。

合并后最多允许 5 个链接。超过限制时不调用模型，也不静默丢弃任何来源；机器人回复用户减少当前消息链接或先解绑固定来源。

固定配置只保存链接，不缓存文档、表格或 Base 内容。每次分析继续通过应用身份实时读取资源，因此能看到来源的最新版本。

如果固定来源被删除、移动、取消共享或应用权限不足，当前请求按现有读取错误处理。服务不会自动解绑该来源。

## 代码边界

新增一个小型群来源存储接口，负责：

- 绑定并执行容量约束。
- 按群查询。
- 按链接解绑。
- 清空群配置。

新增确定性命令解析和处理模块，负责从去除机器人 `@` 后的文本识别配置命令、校验参数并生成回复。

`MessageService` 只做两处编排：

1. 在确认命令之后、普通 Agent 请求之前处理群来源命令。
2. 构建普通群聊来源时注入该群固定来源。

现有 Agent 工具协议、审批写入流程、私聊处理和回复模式保持不变。

## URL 规范化

规范化复用来源注册的飞书域名和路径类型校验。用于唯一性比较时：

- 仅接受 HTTPS。
- 仅接受 `feishu.cn` 及其子域名。
- 仅接受现有 Docx、Wiki、Sheets、Base 路径。
- 移除 URL fragment。
- 对查询参数按名称和值排序。
- 保留影响资源定位的查询参数。
- 域名使用小写。

规范化逻辑由来源注册和群来源命令共同使用，避免两个入口产生不同的支持范围。

## 并发与错误处理

绑定操作使用 SQLite 事务完成容量检查和插入，防止并发消息使群来源超过 5 个。重复绑定通过主键约束保持幂等。

命令失败时返回明确且可操作的错误：

- 私聊使用配置命令：提示仅支持群聊。
- 缺少链接：返回正确命令格式。
- 不支持或非飞书链接：指出对应链接不受支持。
- 新增后超过 5 个：不写入任何新链接，并提示当前数量和可用名额。
- SQLite 写入失败：不声称配置成功。

配置命令继续使用现有 `processed_messages` 去重，重复事件不会重复操作。

## 日志

新增结构化配置日志，记录：

- 操作类型。
- `chat_id`。
- 操作者 `sender_id`。
- 来源类型和操作数量。
- 成功或失败状态。

不记录读取到的文档正文，也不在新增日志中复制链接查询参数。

## 测试

采用垂直切片的简化 TDD，覆盖公开行为：

1. 群成员可以绑定一个有效来源，随后普通分析自动获得该来源。
2. 重复绑定保持一个记录并返回已固定状态。
3. 单次或累计绑定超过 5 个时整次写入失败。
4. 查看命令按添加时间返回当前配置。
5. 单个解绑只影响精确匹配来源。
6. 清空命令移除本群全部来源。
7. 私聊配置命令被拒绝，普通私聊不注入群来源。
8. 固定来源与消息临时来源合并并按规范化 URL 去重。
9. 合并后超过 5 个时不调用 Agent。
10. 关闭并重新打开同一 SQLite 文件后配置仍存在。
11. 并发绑定不会突破 5 个来源上限。

## 非目标

首版不包含：

- 群主或管理员权限控制。
- 固定来源自动过期。
- 交互卡配置界面。
- 固定来源内容缓存。
- 私聊个人固定来源。
- 文件夹、云空间搜索或自动发现来源。
- 在一条消息中同时配置来源并执行分析。
